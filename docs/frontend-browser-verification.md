## Reproduction

Use the already prepared disposable local PostgreSQL database. The test seeds/upserts only synthetic `PW-*` records and never contacts a remote database. On Windows PowerShell, from the repository root:

```powershell
$env:DATABASE_URL = 'postgresql://postgres@127.0.0.1:55432/risklens_perf_test?schema=public'
$env:DIRECT_URL = $env:DATABASE_URL
$pwBytes = [byte[]]::new(24)
$pwRng = [Security.Cryptography.RandomNumberGenerator]::Create()
$pwRng.GetBytes($pwBytes)
$pwRng.Dispose()
$env:RISKLEN_E2E_PASSWORD = [Convert]::ToBase64String($pwBytes)
npm.cmd --prefix frontend ci
npm.cmd --prefix frontend run test:e2e
```

The random password is used only by the disposable browser fixtures and is not written to the repository or printed. The config generates a process-local JWT secret. The current configuration launches the installed Chrome channel; if Chrome is absent, install Google Chrome locally or switch Playwright to its managed Chromium browser and run `npx playwright install chromium` from `frontend`.

The test command starts the backend on `127.0.0.1:4000` and Vite on `127.0.0.1:5173`. Do not replace the database URL with production credentials.

## Remaining limitations

- Transaction filtering currently covers status only; there are no date, amount, or transaction-type controls in the UI.
- Settings is intentionally read-only and describes deployment-managed configuration; it does not provide configuration editing.
- Browser results cover the synthetic local dataset and local Chrome runtime. They do not establish production latency or verify a deployed browser environment.
